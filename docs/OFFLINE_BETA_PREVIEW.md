# Preview a Launch & Own website locally (no accounts or paid services)

The beta onboarding service is not yet publicly accessible while OAuth registration and domain setup finish. This tool lets a developer or invited tester inspect **exactly the website HTML Launch & Own would publish**, without GitHub OAuth, Cloudflare credentials, an AI model, internet access or any infrastructure changes.

Requires **Node.js 22+**. The commands are run from this repository's root.

## 1. Generate a static preview

```sh
node scripts/export-preview.mjs --input examples/willow-studio.json --out ./site-preview
```

The sample is a **fictional** photography business with a four-page website. The command creates a brand-new `site-preview/` folder containing `index.html`, `about/index.html`, `services/index.html`, `contact/index.html` and `preview-manifest.json`.

The manifest records each page's SHA-256 and the **entire approved four-page bundle digest** computed using the same production renderer. It doesn't contain provider secrets. A single-page site can be generated by removing `"layout": "multi-page"` from the JSON.

**No existing folder is ever overwritten.** Choose another output directory for new iterations, or manually remove the earlier local preview folder if no longer needed. Invalid copy, unsupported themes/layouts and malicious content are rejected or HTML-escaped before any output is written.

## 2. View the website in your browser

```sh
node scripts/serve-preview.mjs --dir ./site-preview --port 4173
```

Open **http://127.0.0.1:4173/** in a browser on the same machine. The server binds **only to localhost**, not your LAN or the internet. It exposes only the known static Home/About/Services/Contact routes; it never serves `.env`, manifest files, arbitrary paths or directory listings. Press **Ctrl+C** to stop it.

You can change the JSON input to preview another real business, but only use contact details you are comfortable storing locally. The contact email becomes public if that preview is later approved and deployed to a public website.

## Approval and production limits

- This is a **local demonstration**, not live website provisioning, user authentication or a Cloudflare Pages deployment.
- The export is not an approval action. The actual onboarding application must authenticate the customer, show all pages, record approval against the same bundle digest, and verify exact ownership and GitHub/Cloudflare deployment revisions.
- Pages contain no custom scripts, image uploads, tracking pixels, real contact forms, or third-party fonts. There is no AI inference or provider billing.
- Generated sites use fixed static templates. For marketing or production use, owners must review the factual accuracy, contact details, licensing and accessibility before publication.
- The preview server runs only on the same device. It is **not** a replacement for `onboard.360web.cloud`, which the separate domain agent is configuring.

Run **`npm test`** before proposing changes to the site renderer or export code. Both the exported HTML and its bundle approval digest are regression-tested against the same renderer used in `pipeline/provision-site.mjs`.
